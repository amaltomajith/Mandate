01 Overview

The one-paragraph version, if you read nothing else.

Mandate is an agentic spending firewall — a policy-enforcement layer that sits between an AI agent and Razorpay. An agent (a piece of software, not a human) asks Mandate for permission to move money. Mandate checks whether that agent still has a valid standing authorization (a mandate), works out which independently-governed policy domain the request belongs to, evaluates that domain’s rules, and either lets the real Razorpay call through, escalates it to a human, or blocks it outright — then remembers exactly why, forever, so the decision can be explained later.

Nothing here is simulated at the edges: agents sign real requests with real Ed25519 keys, allowed actions are real Razorpay API calls, and every decision is a real row in a real database that the dashboard reads live.

03 Two authentication layers

A recurring point of confusion: there are two separate identity systems in play, gating two separate kinds of caller.

ClerkWeb Bot Auth
GatesThe dashboard — a human merchant/api/mcp — an AI agent
MechanismEmail/password or Google OAuth sessionEd25519 signature over every request (RFC 9421-shaped)
Identity lives inClerk’s own hosted serviceagents.public_key in Supabase
Proves“I’m an authorized person”“This exact request came from this exact registered key”
Failure modeRedirected to /loginprotocol_reject — caught before policy logic ever runs

They never overlap: a merchant never signs a request, and an agent never has a Clerk session.

04 Core concepts

Seven nouns. Everything else in the system is built from these.

Agent

A registered identity (an Ed25519 keypair) representing one piece of calling software. Accumulates its own trust score from its own history.

Policy domain

An independently-governed zone — its own rules, its own approval queue. An action lands in one based on what it is, never who called it.

Policy rule

One of four types — cap, velocity, category_block, step_up — belonging to exactly one domain.

Mandate

A standing authorization for one agent to act on one customer’s behalf. Revoking it blocks every future action under it, instantly.

Trace

A permanent record of one decision — what was asked, what domain/rule governed it, what happened, and why, in plain language.

Escalation

What a step_up rule produces instead of a block — sits in a queue until a human approves or denies it.

Trust score

0–100 per agent. Starts at 50, moves with its own approval/block/escalation history and account age.

05 Agents vs. domains

The single most important distinction in this codebase, because it looks like one idea and is actually two independent axes.

Agent answers “who.” Domain answers “what kind, and therefore which rules.”

Checkout AgentBackground Traffic Bot
calls order.create → routed to Purchases domain → routed to Purchases domain
calls subscription.create → routed to Recurring Mandates domain never calls this

Read down a column: the same agent lands in two different domains depending on what it’s doing. Read across a row: two different agents land in the same domain, governed by the exact same rule, regardless of who triggered it. Neither axis can substitute for the other — collapsing them would make it impossible to answer either “who do I trust” or “which rule applies here” on its own.

07 The four MCP tools

Deliberately exactly four, reused for every domain and every agent — no per-domain or per-agent tool variants.

ToolDoesReal side effect?

08 Why one endpoint, not one per domain

The architectural fork that’s easy to get wrong: route by content, or route by address?

The per-domain version also can’t survive a merchant creating a new domain from the canvas without dynamically provisioning a new route — a much harder problem, for no functional gain over reading action_type and category off the same request.

11 What’s real vs. illustrative

The specific, current caveats worth knowing before you demo this.

Real

Every allowed action is a genuine Razorpay test-mode API call. Web Bot Auth signature verification is real Ed25519 cryptography. Trust scores, traces, and mandate state are computed from actual history, not fixtures.

Labeled, not hidden

Clerk is still running on development-instance keys (the visible badge is accurate, not a bug). subscription.create falls back to a clearly-flagged simulated mandate object if Razorpay Subscriptions isn’t activated on the connected account. RazorpayX payouts were removed rather than stubbed: they need a registered business Razorpay itself gates, so they could never execute here.
